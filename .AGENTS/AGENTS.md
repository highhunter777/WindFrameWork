代码规范

代码文件与类定义均遵循单一职责原则。

目录结构清晰、职责明确。

业务模块的代码文件与相关美术资源应放在同一模块目录，并在该目录内继续划分子目录管理。

统一命名规范。

减少重复实现。

注释仅描述当前设计与实现，不记录无关内容。

除 ECS 架构外，遵循面向对象设计规范。

遵循开闭原则：对修改关闭，对扩展开放。

禁止硬编码。

按生产级标准实现，注重可扩展性。

架构规范

分层与依赖：客户端为 App → Modules → Kits / Core → Shared；服务端为 Server.* → Shared；客户端与服务端互相不可见，唯一交集为 Shared。

依赖方向由 asmdef 与 csproj 强制，不依赖约定。

契约归属：接口与对外事件随功能模块存放（<模块>/Contracts、Contracts/Events），禁止集中式接口目录。

容器：访问只经 IServiceRegistry / IServiceResolver；实现可替换（DI 等变体独立成程序集，不并入 Core 本体）。

服务定位器：注册只发生在组合根与模块注册阶段；纯 C# 类优先构造注入；解析仅允许出现在表现层边界类型。

模块规则：功能模块自包含 Contracts / Runtime / Testing / Content / Tests / Editor；跨模块只依赖对方 Contracts；仅组合根可引用全部 Runtime。

ECS：可选机制，独立程序集、用才引；框架只提供机制不含业务组件；同一逻辑只在一个范式内实现。

热更边界：框架全部 AOT；热更仅覆盖热更侧程序集与 Lua 脚本；AOT 程序集禁止引用热更程序集，桥接仅经 IHotEntry 契约与反射。

共享层：零 UnityEngine 依赖，语法与 API 以 netstandard2.1 + C# 9 为上限；仅当双端真实复用时下沉，不以纯 C# 为由下沉。

服务端：使用 .NET 原生 DI 与生命周期托管，不移植客户端服务定位器与热更机制。

文档规范

设计文档与施工进度记录分离。

设计文档仅保留最新设计；进度记录仅保留最新进度。

代码完成后，同步回写对应文档。

工具规范

PowerShell 脚本统一使用 pwsh。

资源规范

代码和脚本资源可纳入版本管理。

配置资源、预制体模板资源及其直接依赖资源、场景资源及其直接依赖资源，可纳入版本管理。

第三方付费资源不纳入版本管理。

热更与打包产物（热更程序集、补充元数据、资源包）不纳入版本管理。

其余类型资源不纳入版本管理。
